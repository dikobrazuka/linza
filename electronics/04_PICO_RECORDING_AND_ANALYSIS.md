# USB-запись CDM324 IF на Pico и обработка исходных данных

**Ревизия 09.11, программный шаблон пока не испытан на конкретном Pico + OPA2365.** Использовать только после безопасной проверки платы по electronics/01_CDM324_OPA2365_PICO_SCHEMATIC.md.

## Нужное ПО

- Pico RP2040 с установленным **MicroPython** (только после проверки совместимости с имеющейся платой).
- USB-A→Micro-USB **data** кабель; ПК Windows; Thonny (позволяет отправлять файл и открыть REPL), Python 3 + NumPy для анализа.
- `electronics/pico_cdm324_capture.py` — однократная запись по 4096 отсчётов, nominal Fs 10000 Гц; вывод в USB сериал **только после** завершения измерения.
- `tools/analyze_cdm324_if.py` — RMS в вольтах, DC, пиковая частота FFT и признак обрезания у крайних значений АЦП.

## Порядок

1. Сначала проверить мультиметром U1.8=3.3 В, VREF~1.65 В, U1.1/U1.7~1.65 В и отсутствие провала/перенапряжения на GP26. Осциллографом исключить генерацию и пик выше 3.3 В; если не можете — статус невалидирован, не проводить точные количественные замеры.
2. Установить MicroPython на Pico через официальную процедуру BOOTSEL/USB. В Thonny выбрать интерпретатор MicroPython (Raspberry Pi Pico), загрузить скрипт `electronics/pico_cdm324_capture.py` или открыть и выполнить.
3. Для записи без движущихся объектов выполнить в REPL: `capture_one('BACKGROUND_01')`. После 0.4096 с снимка на экране появятся BEGIN_CDM324_CSV, строка метаданных, заголовок sample_index,adc_u16, отсчёты, END_CDM324_CSV. Сохранить весь фрагмент вывода в UTF-8 текстовый .csv, без ручного изменения цифр.
4. Посмотреть в метаданных **overruns** — если >0, данный capture нельзя считать регулярным Fs и использовать для точной FFT. Фактическая последовательность отсчётов в MicroPython имеет джиттер даже при overruns=0. Для прецизионной обработки заменить реализацию на Pico C SDK ADC+DMA по hardware clock или внешний АЦП.
5. Проверить capture с пластиной, движущейся к радару/от радара: `capture_one('PLATE_01')` (потом PLATE_02/03). Записывать также расстояние, скорость, фон, версию платы/настройки gain в журнал электроники.
6. На ПК: `python -m pip install numpy`; затем `python tools/analyze_cdm324_if.py data/experiment/24ghz/PLATE_01.csv --fs 10000 --low-hz 80 --high-hz 1800`. Соотнести пик с f_D≈161 Hz/(m/s) × radial velocity.
7. Не брать одну FFT амплитуду как абсолютную полученную энергию: Hann coherent gain компенсируется для **одиночного спектрального тона**, но шум / широкая micro-Doppler полоса требуют корректного интегрирования и калибровки. Для относительного сигнала использовать одинаковый gain, одинаковые полосы/режимы, одинаковую дистанцию и серию повторов.
8. Не записывать новые файлы поверх исходных. При любых изменениях аналогового gain объявлять новую ревизию платы и повторять обе сравниваемые конфигурации.

## Ограничения схемы и цифровой части

- Аналоговый RC low-pass R9 3.3k/C5 22n ≈2.19 кГц однополюсный, **не достаточный как идеальный anti-alias фильтр**. При nominal Fs 10 kHz он лишь снижает высокочастотные составляющие, а не устраняет их полностью.
- Выход CDM324 — Doppler IF без дальности; R^-4, угол, микродоплер лопастей и фон могут менять амплитуду. Это **не** calibrated RCS и не абсолютные dBsm.
- Один канал без I/Q не даёт направление движения по знаку Doppler.
- Для flight demo протокол docs/22_DJI_FPV_24GHZ_FLIGHT_DEMO.md. Pico MicroPython single-shot подходит в первую очередь для **контролируемой настольной демонстрации**, а не для гарантированной непрерывной синхронизированной записи полёта.
