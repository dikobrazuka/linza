Версия 1 / 2026-11-09. Этот файл направляет Codex, не заменяет инженерные протоколы.

**Разрешение конфликта:** последняя неотменённая D-xxx инженерная запись → специфический протокол своей ветки → центральный PROJECT_MEMORY. Примеры внутри старого README или board legacy не supersede новое D-032. Не переписывать Ø120 во всех файлах: в DE-10 это правильное значение. Не менять Ø200 на 120 у PLA.

## Данные для UI

### project.json

`specimens`: массив 3 разных физических конструкций. `target` — объект заказной цели (его не добавлять как четвёртую линзу). `systems`: общая 5-GHz VNA система и 24.125-GHz CDM324. Состояние `planned` означает проект, не фото выполненного эксперимента.

### procurement.json

32 `rows`. Каждая строка:
- `id` — стабильный ключ;
- `original_row` — строка пользовательской корзины;
- `track` — направление;
- `title`, `purchase_quantity`, `line_total_rub`, `source_url`, `note`;
- `status: planned`, `ordered_at: null`, `received_at: null`.

**Важно:** `line_total_rub` — **вся стоимость строки (упаковки/числа заказанных единиц)**, а НЕ цена за 1 единицу. Не делать `purchase_quantity * line_total_rub`: итог 24267 ₽ превратится в неверный. Можно выводить условную цену за единицу как line_total/qty с явным пояснением, но первоначальные лоты часто продаются упаковками. Товары 32 шт. не значит 32 отдельных мелких элемента — 32 строки корзины.

`existing_resin_plan`: DE-10 1 кг / 14000 ₽ **не входит** в 24267 ₽. Дополнительные расходы TBD и неопознанные 5996 ₽ не включать в известный итог. Заявлять общую финальную обеспеченную стоимость нельзя.

### actions.json

24 рабочих действия с `id`/направлением/`steps`/`document`/`status`/`evidence`. Это **редакционный план**. Миграция личного прогресса из `site/board.html` по **стабильным IDs** требует отдельного mapping, а не удаления старого localStorage. Новые `id` не совпадают 1:1 с legacy action IDs; Codex должен сделать явное сопоставление и указать это в тестах.

## Риски текущего сайта, обнаруженные при аудите

- `site/work.js`: собственная захардкоженная коллекция задач, не читает `actions.json`.
- `site/board.html`: большой `defaultPlan` и **устаревший `defaultBudget`** с собственным набором значений. Пользовательская смета `linza-budget-v1` в localStorage может содержать правки; не удалять.
- `site/team-addon.js`, `site/drone-addon.js`, `site/shell-addon.js`, `site/board-upgrade.js`: дописывают/переименовывают WBS при загрузке. Несогласованное изменение ведёт к дублям.
- `site/explain.js` по умолчанию выбирает 120 мм — это **нормально только для DE-10**, но UI должен явно показывать возможность Ø200 PLA как независимый объект.
- В `site/board.html` уже есть правильная текстовая общая сумма, но **редактируемая ниже таблица — старый черновик** и не отражает реальные 32 позиции. Нужно визуально и функционально разделить, иначе пользователь воспринимает её как настоящую смету.
- Сайт использует `localStorage` и пока не синхронизирует состояние между пользователями/аккаунтами. GitHub Pages — статический хостинг, не база данных.
- В GitHub Actions Pages публикуется только `site/`, поэтому JSON должны лежать в `site/data/` и загружаться по относительным URL без `/linza/` хардкода.
- Нет доказательств реальных RF-измерений и пайка IF-AFE-R1 пока не прошла hardware verification.

## Минимальный acceptance test

1. `site/data/project.json` содержит три экземпляра 200/120/80, частоты 5/5/24.
2. `site/data/procurement.json` ровно 32 строки, сумма `line_total_rub` ровно 24267; DE-10 ещё +14000 отдельно; отсутствие статуса `received` без подтверждения.
3. `site/data/actions.json` имеет уникальные непустые IDs и документы, ссылки реально существуют в repo.
4. На сайте можно открыть каждую инструкцию. Суммы и свойства не дублируются самостоятельным неконтролируемым литералом в нескольких местах.
5. В WBS старые статусы не теряются после обновления. Есть экспорт/импорт и явная надпись «локально в браузере».
6. Корректно отрабатывает отсутствие JSON/сетевая ошибка без пустой страницы.
7. Не появляется «+10 dB measured» или «24GHz RCS proven» без соответствующих реальных данных.
8. GitHub Pages работает в браузере на desktop/mobile; JS/HTML validation и Python CI зелёные.
